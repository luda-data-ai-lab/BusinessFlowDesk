## 1. 시작하기

### 접속

- 배포 주소로 접속하거나, 로컬에서 실행합니다.
  ```bash
  pnpm install
  pnpm dev              # http://localhost:5173
  pnpm dev --port 5175  # 포트 변경 시 (npm은 npm run dev -- --port 5175)
  ```
- 로그인은 없습니다. 모든 데이터는 **내 브라우저에만** 저장됩니다.

### 첫 실행

1. 처음 열면 **직군 선택** 창이 나옵니다. 내 역할에 가장 가까운 것을 고르고 **시작하기**를 누르세요. (헤더에서 언제든 바꿀 수 있습니다.)
2. 빈 캔버스가 보이면 아래 **프롬프트 바**에 업무를 설명하거나, **템플릿에서 시작**을 눌러 예제 플로우를 불러옵니다.

### 데모 모드 안내

서버에 `CLAUDE_API_KEY`가 설정되지 않으면 **데모 모드(로컬 규칙 기반)** 로 동작합니다. 문장을 단계로 나눠 간단한 플로우를 그려주지만, 실제 AI만큼 정교하지 않습니다. 생성 후 노란 안내 배너가 뜨면 데모 모드입니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더: 로고 · 제목 · 내 플로우 · 템플릿 갤러리 · 직군 · 내보내기 · 언어 │
├──────────┬───────────────────────────────────────────────────┤
│ 사이드바  │  캔버스                                            │
│ - 노드    │   ┌ 툴바: ↶ ↷ | ⇅ ↓/→ ▥ | + − ⛶  N노드·M연결 ┐       │
│   팔레트  │                                                   │
│ - 속성    │           (플로우차트)                 [미니맵]     │
│   패널    │                                                   │
├──────────┴───────────────────────────────────────────────────┤
│ 프롬프트 바: [수정/새 플로우] 입력창                [생성]      │
└──────────────────────────────────────────────────────────────┘
```

| 영역            | 역할                                                                          |
| --------------- | ----------------------------------------------------------------------------- |
| **헤더**        | 플로우 제목 편집, 저장된 플로우 목록, 템플릿, 직군 전환, 내보내기, 한/영 전환 |
| **노드 팔레트** | 노드를 캔버스로 드래그하거나 클릭해서 추가                                    |
| **속성 패널**   | 선택한 노드/연결선의 라벨·설명·담당부서·소요시간·색상·타입 편집               |
| **캔버스 툴바** | 실행 취소/다시 실행, 자동 정렬, 방향 전환, 스윔레인, 확대/축소, 화면 맞춤     |
| **미니맵**      | 전체 플로우 위치 확인, 클릭해서 이동                                          |
| **프롬프트 바** | 자연어로 생성 또는 수정 요청                                                  |

사이드바는 헤더 왼쪽 `⇤` 버튼으로 접을 수 있습니다.

## 3. 플로우 생성하기

### 새 플로우 생성

1. 프롬프트 바 왼쪽에서 **새 플로우**가 선택되어 있는지 확인합니다.
2. 업무를 문장으로 설명합니다.
   > 예) 고객이 주문하면 재고를 확인하고, 재고가 있으면 결제 → 출고, 없으면 입고 대기 후 알림을 보내줘
3. **Enter**(또는 **생성** 버튼)로 전송합니다. 줄바꿈은 **Shift+Enter**.
4. 몇 초 후 플로우가 그려지고 화면에 맞춰 정렬됩니다.

**잘 나오는 프롬프트 팁**

- 시작과 끝을 명확히: "고객 문의 접수부터 처리 완료까지"
- 분기는 조건과 결과를 함께: "승인되면 A, 반려되면 B로"
- 담당·시간을 넣으면 노드에 표시됩니다: "영업팀이 1일 내 견적서 작성"
- 병렬 작업은 "동시에", "각각" 같은 표현을 사용

### 기존 플로우 수정

1. 프롬프트 바에서 **수정**을 선택합니다.
2. 바꾸고 싶은 내용을 설명합니다.
   > 예) 결제 다음에 "부정거래 검수" 단계를 추가해줘 / 반려 분기를 삭제해줘 / 모든 단계에 담당부서를 넣어줘
3. AI가 현재 플로우를 반영해 다시 그립니다. 마음에 들지 않으면 **Ctrl+Z**로 되돌립니다.

프롬프트 바 위의 **추천 프롬프트 칩**은 현재 직군에 맞는 예시입니다. 클릭하면 입력창에 채워집니다.

## 4. 직군(관점) 선택

같은 업무라도 보는 사람에 따라 필요한 정보가 다릅니다. 직군을 바꾸면 **AI가 강조하는 요소와 용어**가 달라집니다.

| 직군              | 특징                                           |
| ----------------- | ---------------------------------------------- |
| **현업 담당자**   | 업무 단계·담당부서·소요시간 중심의 실무 플로우 |
| **PM / 기획자**   | 마일스톤·의존관계·리스크 포인트 강조           |
| **개발자**        | API 호출·데이터 흐름·에러 핸들링 분기          |
| **경영진**        | 고수준 요약과 의사결정·KPI 포인트              |
| **컨설턴트 / SI** | As-Is 프로세스 맵핑, 역할/레인 구분            |

- 헤더의 **직군** 드롭다운에서 즉시 변경할 수 있습니다.
- 직군은 **다음 생성부터** 적용됩니다. 이미 그려진 플로우는 바뀌지 않으니, 다른 관점으로 보고 싶다면 같은 프롬프트로 다시 생성하세요.
- 템플릿 갤러리에서는 현재 직군에 맞는 템플릿이 **추천**으로 먼저 표시됩니다.

## 5. 캔버스에서 편집하기

### 노드

| 작업      | 방법                                                                       |
| --------- | -------------------------------------------------------------------------- |
| 추가      | 팔레트에서 캔버스로 **드래그**, 또는 팔레트 항목 **클릭**                  |
| 이동      | 노드를 드래그                                                              |
| 선택      | 클릭. **Shift+드래그**로 영역 선택                                         |
| 라벨 수정 | 노드 **더블클릭** → 입력 → Enter                                           |
| 상세 편집 | 노드 선택 → 오른쪽 **속성 패널**에서 설명·담당부서·소요시간·색상·타입 변경 |
| 삭제      | 선택 후 **Delete** / **Backspace**, 또는 속성 패널의 **삭제**              |

### 연결선

| 작업      | 방법                                                        |
| --------- | ----------------------------------------------------------- |
| 연결      | 노드 가장자리의 **핸들(작은 점)** 을 다른 노드로 드래그     |
| 조건 라벨 | 연결선 **더블클릭**, 또는 선택 후 속성 패널의 **조건 라벨** |
| 선 스타일 | 속성 패널에서 **실선/점선**                                 |
| 삭제      | 선택 후 Delete                                              |

**분기(◇) 노드**는 아래쪽 핸들이 **예**, 오른쪽 핸들이 **아니오**입니다. 여기서 연결하면 라벨이 자동으로 붙습니다.

### 정렬과 보기

| 툴바 버튼 | 기능                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------- |
| ↶ ↷       | 실행 취소 / 다시 실행                                                                                   |
| ⇅         | **자동 정렬** — 겹치거나 흩어진 노드를 깔끔하게 재배치. 직접 옮긴 노드는 유지됩니다(스윔레인 모드 제외) |
| ↓ / →     | **방향 전환** — 위→아래(TB) ↔ 왼→오른(LR)                                                               |
| ▥ / ▤     | **스윔레인(부서별)** 켜기/끄기                                                                          |
| 🖥         | **시스템 레인** — 관련 시스템(ERP, CRM …) 기준으로 그루핑                                               |
| + −       | 확대 / 축소 (마우스 휠로도 가능)                                                                        |
| ⛶         | **화면 맞춤** — 전체 플로우가 한눈에 보이도록                                                           |

생성 직후에는 글자가 읽히는 크기를 유지하며 **시작 노드부터** 보여줍니다. 큰 플로우는 스크롤하거나 ⛶로 전체를 보세요.

| 아이콘 | 타입              | 용도                                      |
| ------ | ----------------- | ----------------------------------------- |
| ●      | **시작**          | 프로세스의 출발점                         |
| ◎      | **종료**          | 프로세스의 끝                             |
| ▭      | **업무**          | 일반 작업 단계 (담당부서·소요시간 표시)   |
| ◇      | **분기**          | 조건 판단. 예/아니오로 갈라짐             |
| ⊞      | **하위 프로세스** | 별도 플로우로 상세화되는 묶음 단계        |
| ⬡      | **시스템**        | 외부 시스템·API·DB 호출                   |
| ▱      | **데이터**        | 문서·데이터 산출물                        |

속성 패널의 **노드 타입**에서 이미 만든 노드의 타입을 바꿀 수 있습니다.

## 7. 스윔레인(부서별 레인)

각 노드의 **담당부서** 값으로 캔버스를 레인으로 나눠, "누가 무엇을 하는지"를 한눈에 보여줍니다.

1. 툴바에서 **▥** 를 누르면 켜집니다.
2. 세로 방향(TB)에서는 **열**, 가로 방향(LR)에서는 **행**으로 레인이 그려집니다.
3. 담당부서가 없는 노드는 **미지정** 레인에 모입니다.
4. 노드를 **다른 레인으로 드래그**하면 담당부서가 그 레인으로 바뀝니다.
5. 스윔레인 상태는 플로우별로 저장되며, PNG/SVG 내보내기에도 레인이 함께 그려집니다.

### 시스템별 그루핑

각 노드에는 **관련 시스템**(ERP, CRM, 결제 PG, 외부 API 등) 속성이 있습니다. AI 생성 시 자동으로 추론되며, 속성 패널에서 직접 입력·수정할 수 있습니다(기존 시스템명이 자동완성됩니다).

- 툴바의 **🖥** 을 누르면 부서 대신 **시스템 기준 레인**으로 캔버스가 재배치되어, 어떤 단계가 어떤 시스템에서 수행되는지 한눈에 보입니다. 시스템이 없는 수작업 단계는 "수작업 / 시스템 없음" 레인에 모입니다.
- 시스템 레인에서 노드를 다른 레인으로 드래그하면 그 노드의 시스템이 바뀝니다.
- **Markdown**·**PPTX** 내보내기에는 "시스템별 단계" 표(시스템 × 단계 매트릭스)가 자동 추가됩니다.

> 팁: 생성 프롬프트에 "담당부서를 포함해서" 라고 쓰거나, 수정 모드에서 "모든 단계에 담당부서 넣어줘" 라고 요청하면 레인이 바로 채워집니다.

## 8. 템플릿 갤러리

자주 쓰는 업무 플로우를 골라 바로 시작할 수 있습니다.

- 열기: 헤더 **🧩 템플릿 갤러리**, 또는 빈 캔버스의 **또는 템플릿에서 시작**
- **검색**: 템플릿 이름·설명·단계 이름으로 찾기
- **내 직군만**: 현재 직군에 해당하는 템플릿만 표시. 해당 템플릿에는 **추천** 배지가 붙고 위에 정렬됩니다.
- 카드를 클릭하면 **새 플로우**로 열립니다. 이미 작업 중인 플로우가 있으면 확인 창이 뜨며, 기존 플로우는 **내 플로우**에 그대로 남습니다.

| 템플릿                | 추천 직군        |
| --------------------- | ---------------- |
| 주문 → 배송 처리      | 현업, 경영진     |
| 고객 클레임 처리      | 현업, PM         |
| 채용 프로세스         | 현업, 경영진     |
| 신규 기능 기획–출시   | PM, 개발자       |
| CI/CD 배포 파이프라인 | 개발자           |
| 장애 대응(인시던트)   | 개발자, 현업     |
| 예산 승인             | 경영진, 현업     |
| 컨설팅 제안–수행      | 컨설턴트, 경영진 |
| 신규 입사자 온보딩    | 현업, PM         |

템플릿에는 담당부서가 미리 들어 있어 **스윔레인**을 바로 켜볼 수 있습니다. 불러온 뒤에는 일반 플로우처럼 프롬프트 수정·편집이 가능합니다.

## 9. 저장과 내 플로우

- 편집 내용은 **자동 저장**됩니다(브라우저 localStorage). 새로고침해도 유지됩니다.
- 헤더 **내 플로우 (N)** 에서 저장된 플로우를 전환·삭제할 수 있습니다.
- **새 플로우**(프롬프트 바 왼쪽 버튼)를 누르면 현재 플로우는 목록에 남고 빈 캔버스가 열립니다.
- 제목은 헤더의 제목 칸을 클릭해 바꿉니다.

**주의**

- 데이터는 **이 브라우저·이 기기**에만 있습니다. 브라우저 데이터를 삭제하거나 다른 기기에서 열면 보이지 않습니다. 중요한 플로우는 **JSON 백업**으로 내려받으세요.
- 저장된 플로우가 10개를 넘으면 정리 안내가 표시됩니다.

## 10. 내보내기·공유

헤더 **내보내기** 메뉴에서 선택합니다.

| 항목               | 결과                                                          | 용도                                                 |
| ------------------ | ------------------------------------------------------------- | ---------------------------------------------------- |
| **PNG 이미지**     | 고해상도 이미지(2x)                                           | 슬라이드·문서·메신저 첨부                            |
| **SVG 벡터**       | 확대해도 깨지지 않는 벡터                                     | 인쇄물, 디자인 툴                                    |
| **PPTX 슬라이드**  | 1장: 다이어그램, 2장~: 단계 목록 표, 마지막: 시스템별 단계 표 | 보고서·발표 자료에 바로 삽입                         |
| **JSON 백업**      | 플로우 전체 데이터                                            | 보관, 다른 브라우저/기기로 이동                      |
| **JSON 불러오기**  | 백업 파일을 새 플로우로 복원                                  |                                                      |
| **Mermaid (.mmd)** | Mermaid `flowchart` 코드                                      | GitHub·Notion·Obsidian 등 Mermaid 지원 도구에 붙이기 |
| **Markdown 문서**  | 제목·단계 목록·전환 표·Mermaid 다이어그램                     | 위키, PR 설명, 업무 매뉴얼                           |
| **공유 링크 복사** | 플로우가 담긴 URL을 클립보드로                                | 로그인 없이 동료에게 전달                            |

### 공유 링크

- 서버에 저장하지 않고 **URL 자체에 플로우가 압축되어** 들어갑니다.
- 받은 사람이 링크를 열면 **내 플로우에 복사본**이 저장되고 바로 편집할 수 있습니다. 원본은 바뀌지 않습니다.
- 노드가 매우 많은 플로우(URL 32KB 초과)는 공유 링크 대신 JSON 백업을 이용하세요.

## 13. 자주 묻는 질문

**Q. 생성 결과가 너무 단순해요.**
데모 모드인지 확인하세요(노란 배너). 실제 AI 모드에서는 프롬프트에 조건·담당·순서를 구체적으로 적을수록 좋아집니다. 수정 모드로 "더 세부 단계로 나눠줘" 라고 요청할 수도 있습니다.

**Q. 플로우가 사라졌어요.**
헤더 **내 플로우**에서 다른 플로우로 전환되어 있지 않은지 확인하세요. 브라우저 데이터를 지웠거나 다른 브라우저/시크릿 모드라면 복구할 수 없습니다. JSON 백업을 권장합니다.

**Q. 자동 정렬을 눌렀는데 일부 노드가 안 움직여요.**
직접 옮긴(고정된) 노드는 위치를 유지합니다. **방향 전환**을 한 번 하거나 **스윔레인**을 켜면 전체가 다시 정렬됩니다.

**Q. 내보낸 PNG에 노드가 잘려요.**
전체 플로우와 스윔레인 헤더까지 포함해 내보내도록 되어 있습니다. 문제가 반복되면 **⛶ 화면 맞춤** 후 다시 시도하고, 그래도 잘리면 이슈로 알려주세요.

**Q. 다크 모드는 어떻게 켜나요?**
운영체제/브라우저의 다크 모드 설정을 따릅니다.

**Q. 내 데이터가 외부로 전송되나요?**
플로우 저장·편집·내보내기는 모두 브라우저 안에서 처리됩니다. **생성/수정 요청 시에만** 프롬프트와(수정 모드일 때) 현재 플로우가 서버를 거쳐 AI에 전달됩니다. API 키는 서버에만 있고 브라우저로 노출되지 않습니다.
